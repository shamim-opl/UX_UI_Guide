## এটা কী?

**ডিজাইন টোকেন** হলো একটা নামযুক্ত, পুনঃব্যবহারযোগ্য ডিজাইন সিদ্ধান্ত (রং, স্পেসিং, ফন্ট সাইজ ইত্যাদি), যা সরাসরি হার্ডকোড করা মানের বদলে ব্যবহার করা হয়। যেমন `#1A8917` সরাসরি লেখার বদলে `--color-accent` নামের একটা টোকেন ব্যবহার করা, যার মান পরে এক জায়গায় বদলালে পুরো প্রোডাক্টে বদলে যায়।

<Callout type="guideline">
এই প্ল্যাটফর্ম নিজেই ডিজাইন টোকেন ব্যবহার করে তৈরি — `--color-accent`, `--space-4`, `--text-h1-size` ইত্যাদি টোকেন এখানে ব্যবহৃত হয়েছে, কোনো রং বা স্পেসিং কম্পোনেন্টে সরাসরি হার্ডকোড করা নেই।
</Callout>

## কেন গুরুত্বপূর্ণ?

টোকেন ছাড়া, একটা রং বদলাতে হলে পুরো কোডবেসে সেই হেক্স কোড খুঁজে খুঁজে বদলাতে হয় — ভুল হওয়ার ঝুঁকি বেশি, সময় বেশি লাগে। টোকেন দিয়ে, একটা জায়গায় মান বদলালে পুরো প্রোডাক্টে (এবং লাইট/ডার্ক থিমেও) সামঞ্জস্যপূর্ণভাবে বদলে যায়।

## UI উদাহরণ

```css
/* টোকেন ছাড়া — hardcoded */
.button { background: #1A8917; }

/* টোকেন দিয়ে */
.button { background: var(--color-accent); }
```

থিম বদলালে (লাইট → ডার্ক), `--color-accent`-এর মান বদলে যায়, কিন্তু `.button`-এর কোড একই থাকে।

## টোকেনের স্তর (Tiers)

```text
Global/Core Token   → --green-600: #1A8917 (কাঁচা মান)
       ↓
Semantic Token       → --color-accent: var(--green-600) (অর্থ যোগ করে)
       ↓
Component Token       → --button-primary-bg: var(--color-accent) (নির্দিষ্ট ব্যবহার)
```

সেমান্টিক টোকেন (যেমন `--color-error`) সবচেয়ে গুরুত্বপূর্ণ স্তর — এটা "লাল রং" না বলে "এরর বোঝানোর রং" বলে, যা মানে বহন করে।

## Rules / Best Practices

- টোকেনের নাম *উদ্দেশ্য* অনুযায়ী দাও, *ভিজ্যুয়াল বৈশিষ্ট্য* অনুযায়ী না — `--color-accent` ভালো, `--color-green` খারাপ (রং বদলালে নামটা মিথ্যা হয়ে যায়)।
- প্রতিটা কম্পোনেন্টে সরাসরি হেক্স/পিক্সেল মান লেখা এড়িয়ে চলো — সবসময় টোকেন রেফারেন্স করো।
