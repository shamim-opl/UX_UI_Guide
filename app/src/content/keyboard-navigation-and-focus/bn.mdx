## এটা কী?

**Keyboard Navigation** মানে মাউস বা টাচ ছাড়া শুধু কীবোর্ড (Tab, Shift+Tab, Enter, Space, Arrow keys, Escape) দিয়ে একটা ইন্টারফেসের সম্পূর্ণ কার্যকারিতা ব্যবহার করা যাওয়া — [WCAG](/learn/10-accessibility/wcag-accessibility)-এর "Operable" নীতির মূল অংশ, এবং শুধু মোটর-প্রতিবন্ধী ব্যবহারকারীর জন্য না, স্ক্রিন রিডার ব্যবহারকারী ও পাওয়ার-ইউজারদের জন্যও অপরিহার্য।

## Focus Order

```text
Tab চাপার ক্রম হওয়া উচিত ভিজ্যুয়াল পড়ার ক্রমের সাথে মিল রেখে:

[লোগো] → [সার্চ] → [নেভ আইটেম ১] → [নেভ আইটেম ২] → [মূল কনটেন্ট] → [ফুটার]
```

Focus Order যদি ভিজ্যুয়াল লেআউটের সাথে না মেলে (যেমন CSS দিয়ে এলিমেন্ট ভিজ্যুয়ালি সরানো হয়েছে কিন্তু HTML অর্ডার বদলায়নি), কীবোর্ড ব্যবহারকারী এলোমেলো, অপ্রত্যাশিত ক্রমে জাম্প করবে।

## Focus Trap

একটা [Modal](/reference/components/modal-component) খোলা অবস্থায় Tab চাপলে ফোকাস Modal-এর বাইরে (পেছনের পেজে) চলে যাওয়া উচিত না — এটাকে "Focus Trap" বলে (ফোকাস Modal-এর ভেতরে "আটকে" থাকে যতক্ষণ না বন্ধ হয়)। Modal বন্ধ হলে ফোকাস আগে যেখানে ছিল সেখানে ফিরে যাওয়া উচিত।

## Skip Link

পেজের একদম শুরুতে একটা লুকানো লিংক ("মূল কনটেন্টে যান") থাকা উচিত, যা Tab চাপলে প্রথমে ফোকাস পায় — এতে কীবোর্ড ব্যবহারকারীকে প্রতিটা পেজে বারবার পুরো নেভিগেশন মেনু Tab করে পার হতে হয় না, সরাসরি মূল কনটেন্টে যেতে পারে।

<Callout type="established">
এই প্ল্যাটফর্ম নিজেই প্রতিটা পেজে একটা "স্কিপ টু কন্টেন্ট" লিংক ব্যবহার করে, ঠিক এই কারণে।
</Callout>

## Visible Focus Indicator

প্রতিটা ফোকাসড এলিমেন্টের চারপাশে একটা স্পষ্ট, উচ্চ-কনট্রাস্ট আউটলাইন/রিং থাকা আবশ্যক — WCAG 2.2-এর নতুন সাফল্য মানদণ্ড (2.4.11 Focus Not Obscured) অনুযায়ী ফোকাসড এলিমেন্ট অন্য কোনো এলিমেন্ট (যেমন একটা স্টিকি হেডার) দিয়ে ঢাকা পড়া উচিত না।

## বাস্তব উদাহরণ

একজন কীবোর্ড-শুধু ব্যবহারকারী একটা চেকআউট ফর্ম পূরণ করার সময়: Tab চাপলে প্রথমে ইমেইল ফিল্ড, তারপর পাসওয়ার্ড, তারপর "লগইন" বাটন — এই যৌক্তিক ক্রমে ফোকাস যায়। যদি ফোকাস হঠাৎ পেজের নিচের ফুটারে চলে যায় (ভুল HTML অর্ডারের কারণে), ইউজার সম্পূর্ণ বিভ্রান্ত হয়ে পড়বে।

## Rules / Best Practices

- Native HTML এলিমেন্ট (`<button>`, `<a>`, `<input>`) ব্যবহার করো যেখানে সম্ভব — এগুলোতে কীবোর্ড সাপোর্ট বিনামূল্যে পাওয়া যায়, কাস্টম `<div>`-ভিত্তিক কম্পোনেন্টে ম্যানুয়ালি বানাতে হয়।
- কখনো `outline: none` দিয়ে Focus Indicator সম্পূর্ণ সরিয়ে ফেলো না, বিকল্প স্পষ্ট ইঙ্গিত ছাড়া।
- Escape কী দিয়ে যেকোনো Modal/Dropdown/Overlay বন্ধ করা যাওয়া উচিত।

## সাধারণ ভুল

CSS দিয়ে একটা এলিমেন্টকে ভিজ্যুয়ালি অন্য জায়গায় সরানো (যেমন `order` বা `position`), কিন্তু HTML-এর আসল ক্রম না বদলানো — ভিজ্যুয়ালি ঠিক দেখালেও Tab Order আসল HTML ক্রম অনুসরণ করে, তাই ভিজ্যুয়াল আর কীবোর্ড অভিজ্ঞতা আলাদা হয়ে যায়।
